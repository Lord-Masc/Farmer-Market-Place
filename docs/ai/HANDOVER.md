- Stage 5 close semantics: claim-first (order → shares → settlements → gated open→closed claim). Negotiated path reuses the Stage 4 agreement's order (verified: buyer is the owner, quantity equals the pooled total — else 409 GROUP_ORDER_MISMATCH). Direct path creates the order via escrow (stock check, cannot buy own product; optional locked unit_price from a chosen quote). A requirement with no agreement yet + no product_id is a 409 GROUP_NEGOTIATION_PENDING. Close does NOT require the deadline to have passed — threshold only. Replay works ONLY when the caller sends Idempotency-Key `group-buy-close-<groupId>` (the frontend sends it on every close); any other second close is a 409, and nothing is ever duplicated.
- Stage 5 list semantics: `?status=all` returns open + closed (the "All" tab); `?status=mine` means owned-or-joined (the "My groups" tab). Settlement amounts are integer paise split by largest remainder, so they sum EXACTLY to the order total; `share` is a fraction (contribution/total).
- FLAG — Stage 5 settlements record what each participant OWES toward the pooled order (the group buys as one buyer; the owner pays at checkout). They are not payouts and no money moves in this stage — collection/reconciliation is a later stage. The UI labels them "share of the pooled order total" for exactly this reason.
